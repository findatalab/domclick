## Особенности матрицы
- Пропуски **не заполняются**: NaN остаётся, потому что `HistGradientBoostingRegressor`, XGBoost и LightGBM обрабатывают NaN сами, а заполнение до разбиения на фолды переносит информацию из теста в обучение. Для линейных моделей заполняйте NaN медианой, посчитанной **только на обучающей части** каждого фолда.
- «Неизвестно» и «нет» — разные ответы. Явное отрицание («нет газа», `absent`, «выгребная яма») даёт отрицательный уровень группы (`otsutstvuet`, `without_repair`), а нераспознанный ответ — явный уровень `unknown`. Строки, по которым модель вообще не отвечала, остаются NaN: «не спрашивали» не становится ни «нет», ни «неизвестно». Благодаря этому 300 строк с ответом `unknown` по газу больше не выглядят как «газа нет».
- Планировка и дополнительные строения идут и флагом (есть/нет), и числом: 0 — модель явно не нашла признак в тексте, NaN — ответа по объявлению нет.
- Возраст: `house_age` (год постройки как `2026 - house_age`) и флаг `house_is_new` — дом не старше 3 лет; отдельная колонка с годом была бы линейно зависимой копией.
- Производные признаки: `house_area_per_floor`, `land_to_house_ratio`, `free_land_sotka` (участок минус пятно застройки), `bedrooms_per_100m2`, `bathrooms_per_100m2`, `house_is_new` — считаются после заполнения пропусков, чтобы не терять строки.
- Текстовые флаги (`txt_*`) и метки продавца (`tag_*`) — из карточки, не из извлечений: регулярные выражения Python `re`, поэтому границы слов работают с кириллицей. Они дублируют часть извлечений (газ, вода, водоём, лес) и добавлены как независимая проверка того же сигнала.
- Признаки, производные от цены (`price_per_m2_*`), не строятся, а метка платформы «Выгодная цена» не используется: она вычисляется из цены. Цена за м² используется только для чистки строк и в отчёте о качестве данных.
- Константные колонки, удалённые автоматически (только уровни шоссе): нет. Остальные колонки групп остаются на месте, чтобы схема не зависела от выборки: удаляются только уровни реже `--min-level-count`.

## Как обучать на этой матрице
1. Целевая переменная: `log_asking_price_rub` для скошенного распределения — метрики затем пересчитывайте обратно через `expm1`.
2. Модели: `HistGradientBoostingRegressor` или LightGBM/XGBoost — они нативно работают с NaN.
3. Разбиение: `GroupKFold` с группами из `group_locality` — объявления одного населённого пункта не должны попадать одновременно в обучение и тест.
4. Проверяйте метрики и по сегментам (например, цена за м² в 25-300 тыс. ₽ и цены ниже 5 млн ₽): абсолютная и относительная ошибки живут в разных хвостах.
