## Обработка пропусков
Пропуски **не заполняются**: обе модели — `HistGradientBoostingRegressor`, который сам направляет объекты с NaN в отдельную ветвь. Это принципиально, потому что в матрице **18,275** пропущенных ячеек, и хотя бы один пропуск есть в **1,144** из **1,144** строк (100.0 %). Построчное удаление пропусков оставило бы **0** строк — HistGB сохраняет все данные.

## Ограничения
- `asking_price_rub` — цена предложения, а не подтверждённая цена сделки.
- Валидация групповая (`GroupKFold` по `group_locality`): объявления одного населённого пункта не попадают одновременно в обучение и тест, поэтому оценка консервативнее обычного `KFold`. Группировка не устраняет дубликаты одного физического объекта с разными `listing_id`.
- Вес ансамбля по умолчанию фиксирован (0,5 на лог-шкале). Оптимальный вес из отчёта подобран на out-of-fold прогнозах и потому оптимистичен: для честной оценки подбирайте вес внутри обучающих фолдов или на отдельном наборе.
- LLM-признаки извлечены языковой моделью из текста объявления: они шумные, могут содержать пропуски и ошибки распознавания. Модель на LLM-признаках обучена только на них, поэтому не видит структурных характеристик объекта.
- Целевая переменная скошена (skew ≈ 9,8): RMSE сильно зависит от нескольких дорогих объектов, поэтому рядом приведены MAE и медианная ошибка.
- Признак `badge_mortgage_discount_pct` — прокси продавца/сегмента (корреляция с ценой 0,82, немонотонен по цене). Проверяйте устойчивость результата без группы `badge_*`.
- Прогнозы обрезаются по диапазону обучающей части фолда (включено), поэтому модель не выдаёт цены за пределами наблюдённого диапазона.
- Ансамбль не экстраполирует: для объектов вне обучающего распределения (другой регион, другой тип недвижимости) прогноз не обоснован.
