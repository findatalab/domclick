# Алгоритм итеративной оптимизации признаков и обработки аномальных наблюдений с использованием LLM на примере прогнозирования цен предложения индивидуальных жилых домов

**Наиболее подходящий — пункт 16 специальности 1.2.1:** «Исследования в области специальных методов оптимизации, проблем сложности и элиминации перебора, снижения размерности». 

Ему соответствует основная идея работы: **LLM направляет поиск сочетаний признаков, промптов извлечения и правил обработки аномалий, сокращая число необходимых экспериментов**. Недвижимость выступает примером применения алгоритма. Дополнительная связь — с пунктом 2, посвящённым оценке эффективности и сравнению алгоритмических решений.

## 1. Введение

**1.1. Актуальность задачи.**  
Несмотря на развитие LLM и агентной разработки, классические модели машинного обучения сохраняют практическую значимость. Их качество зависит от представления данных, отбора признаков и обработки ошибочных наблюдений.

**1.2. Проблема использования неструктурированных данных.**  
Тексты могут содержать дополнительные характеристики и сведения для восстановления пропусков. LLM способна извлекать кандидаты признаков, однако полезность этих признаков для прогнозирования устанавливается экспериментально. Требуется выбирать состав признаков, способ нормализации, промпт и правила объединения источников.

**1.3. Ограничения существующего процесса разработки.**  
Перебор вариантов требует доменных знаний, компетенций в ML и значительных затрат. Анализ ошибок может направлять поиск, но нуждается в воспроизводимой процедуре.

**1.4. Цель исследования.**  
Повысить качество и эффективность разработки моделей машинного обучения посредством итеративной оптимизации признакового представления и правил исключения аномальных наблюдений с использованием LLM.

Основная гипотеза: **при одинаковом бюджете экспериментов поиск, направляемый LLM на основе анализа ошибок, позволяет получить лучшее качество либо достичь сопоставимого качества за меньшее число обучений**.

## 2. Методика исследования
### 2.1 Формальная постановка задачи

Представить исходные данные:

\[
D=\{(x_i,d_i,y_i)\}_{i=1}^{N},
\]

где \(x_i\) — структурированные характеристики, \(d_i\) — текст, \(y_i\) — целевая переменная.

Конфигурацию эксперимента определить как

\[
c=(S,p,a),
\]

где:

- \(S\) — набор признаков и правил их преобразования;
- \(p\) — промпт извлечения;
- \(a\) — правило выявления и обработки аномальных наблюдений.

Задача — найти конфигурацию с минимальной валидационной ошибкой **в пределах заданного бюджета**:

\[
c^*=\arg\min_{c\in\mathcal C_B} L_{\mathrm{val}}(c).
\]

Дополнительно учитывать число обучений, время, стоимость обращений к LLM и долю исключённых наблюдений.

Зафиксировать ограничения: отсутствие утечки цели, неизменность внешней оценки и допустимые основания исключения данных.

### 2.2 Алгоритм итеративной оптимизации

**Начальная конфигурация.**  
Построить матрицу из структурированных данных, обучить базовую модель, получить валидационные прогнозы и ошибки.

**Первичное извлечение.**  
С помощью исходного промпта извлечь дополнительные характеристики, проверить цитаты, типы, единицы и статусы. Построить расширенную матрицу и оценить модель.

**Формирование отчёта для LLM.**  
Передавать модели метрики, ошибки по подгруппам, покрытие признаков, противоречия источников и примеры неудачных прогнозов. Разделять целевую метку, доступную для анализа ошибок, и текст для последующего извлечения без цены.

**Генерация изменений.**  
LLM предлагает ограниченное число проверяемых гипотез:

- добавить или удалить признаки;
- объединить синонимичные категории;
- восстановить пропуски;
- уточнить промпт;
- выявить ошибочные единицы или противоречия;
- предложить правила обработки подозрительных наблюдений.

Для каждого изменения фиксировать основание и ожидаемый эффект.

**Проверка кандидатов.**  
Автоматически проверить допустимость предложений, построить новые матрицы, обучить модели и сравнить качество на одинаковых внутренних разбиениях. Сохранять лучшую конфигурацию; ухудшающие изменения отклонять.

**Условия остановки.**  
Остановить поиск при исчерпании бюджета, отсутствии улучшения в течение заданного числа итераций или улучшении меньше порога \(\varepsilon\).

Формулировку «до получения минимального значения» заменить на **«до выполнения критерия остановки с сохранением лучшей найденной конфигурации»**: глобальный минимум такой поиск не гарантирует.

### 2.3 Выявление и обработка аномалий

Определить классы подозрительных наблюдений:

| Класс | Действие |
|---|---|
| Ошибка единиц, парсинга или ввода | Исправление по подтверждённому источнику |
| Противоречивые сведения | Проверка, маркировка, при необходимости исключение из обучения |
| Объект вне заранее заданной области применения | Исключение по общему критерию |
| Редкий, но корректный объект | Сохранение и отдельный анализ качества |
| Большая ошибка прогноза без иных оснований | Анализ модели, без автоматического удаления |

LLM предлагает основания и правила, а исключение выполняется воспроизводимым механизмом. Не допускать удаления объектов только ради улучшения метрики.

Различать **фильтрацию обучающих данных** и **отказ системы от прогноза**. Во втором случае оценивать одновременно ошибку и долю объектов, для которых выдан результат.

### 2.4 Организация экспериментального исследования

**Прикладной набор данных.**  
Описать объявления домов как пример неоднородных данных. Указать формирование подвыборки до 50 млн ₽ и целевую переменную — цену предложения. Зафиксировать область применения до начала поиска.

**Протокол оценки.**  
Использовать вложенную оценку: внутренние разбиения — для итеративного поиска, внешние — для оценки выбранной конфигурации. Внешние ошибки не передавать LLM и не использовать для изменения алгоритма.

**Сравниваемые методы.**

| Метод | Назначение |
|---|---|
| Структурированные признаки | Базовый уровень |
| Однократное извлечение LLM | Эффект без итераций |
| Стандартный отбор признаков и обработка аномалий | Автоматический ориентир без LLM |
| Случайный поиск конфигураций | Проверка эффективности направления поиска |
| Итеративный алгоритм с LLM | Предлагаемый метод |

Задать сопоставимые бюджеты и одинаковую модель-предиктор. Затем проверить перенос результата хотя бы на ещё одну модель. Для подтверждения универсальности желательно добавить второй набор данных со структурированными полями и текстом.

**Исследование компонентов.**  
Поочерёдно отключать изменение промпта, отбор признаков, восстановление пропусков и обработку аномалий.

## 3. Результаты

Представить:

- качество начальной и итоговой конфигураций;
- траекторию метрики по итерациям;
- число экспериментов до достижения заданного качества;
- изменения состава признаков и промпта;
- число исправленных и исключённых наблюдений;
- вклад каждого компонента;
- устойчивость по разбиениям и повторным запускам LLM;
- вычислительные затраты.

Основные метрики регрессии — MAE и RMSE; для эффективности поиска — качество при фиксированном бюджете и бюджет достижения заданного качества.

## 4. Обсуждение

Объяснить, какие предложения LLM оказываются полезными и какие приводят к ухудшению. Рассмотреть зависимость от исходного промпта, модели LLM, полноты текста и доменных знаний.

Отдельно обсудить адаптивное переобучение на валидации, риск удаления сложных корректных объектов и воспроизводимость поиска.

Установить границы обобщения: результаты на объявлениях демонстрируют работоспособность алгоритма, но сами по себе не доказывают эффективность во всех прикладных областях.
