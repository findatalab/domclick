# Воспроизведение результатов статьи

> **Ссылка на статью — TODO.** Авторы, название, издание, год, DOI/URL: _добавить_.
> Репозиторий подготовлен как пакет воспроизведения: данные, код и отчёты, по которым
> проверяются результаты публикации.

Репозиторий воспроизводит полный эксперимент — от исходных выгрузок объявлений Домклик
до сравнения моделей оценки цены предложения:

1. сборка датасета из XLSX-выгрузок (опционально, если датасет уже собран);
2. разведочный анализ и описательная статистика;
3. построение признаков — от базовой пары «площадь дома и участка» до широкой матрицы;
4. обучение и сравнение моделей: линейная регрессия как базовая и градиентный бустинг
   как основная.

Числа (метрики, важности признаков, диагностика остатков) не дублируются в этом файле,
чтобы не расходиться с кодом: отчёты EDA и признаков лежат в `reports/<этап>/`, а
обучающие запуски — в `experiments/<номер>/` (см. раздел «Эксперименты»). Каждый отчёт
пересоздаётся запуском соответствующего скрипта.

## Данные

### Источник

`data/raw/` — 95 выгрузок `.xlsx` (листы вида `https://domclick.ru/pokupka/dom`).
Одна строка — объявление, первая строка — заголовки CSS-классов; число и порядок
столбцов фотографий могут различаться. Поддерживаются `.xlsx`, не старые `.xls`.

### Канонический каталог

`data/dataset/` — каноническое расположение датасета, пути по умолчанию во всех скриптах.
Скрипт сборки (`build_dataset.py`) создаёт в выходном каталоге полный набор файлов:

- `objects.jsonl` — основной датасет, по одному JSON-объекту на строку (1858 записей);
- `objects.csv` — та же таблица, UTF-8 с BOM, разделитель `;`, вложенные списки как JSON;
- `photos_manifest.jsonl` — журнал обработки изображений: ссылка, путь, статус, размеры, SHA-256, время;
- `raw_rows.jsonl` — исходные ячейки с именем файла, листом и номером строки, включая нераспознанные;
- `photos/<listing_id>/` — скачанные изображения, имена по стабильному хешу ссылки;
- `summary.json` — число прочитанных файлов, объектов, ссылок, пропущенных строк и конфликтов;
- `run.log` — сообщения и ошибки.

В приложенной копии `data/dataset/` присутствуют только четыре таблицы и `run.log`:
фотографии и `summary.json` в неё не выгружались, поэтому скрипты анализа работают
без изображений.


### Схема записи

Ключевые поля: `listing_id`, `listing_url`, `object_type`, `price_type`, `currency`,
`asking_price_rub`, `price_per_m2_advertised`, `price_per_m2_computed`, `house_area_m2`,
`land_area_sotka`, `floors`, `address_fragment`, `locality`, `locality_url`, `settlement`,
`highway`, `distance_to_mkad_km`, `description`, `seller_name`, `seller_type`,
`listing_age_text`, `land_use_label`, `tags_seller_claimed`, `badges_platform_claimed`,
`photo_count_advertised`, `photo_urls`, `photo_paths`, `sources`, `conflicts`.

Незаполненные числовые поля имеют значение `null`, а не ноль. В этой выгрузке все записи
относятся к типу `sale__house` и валюте `RUB`, поэтому поля `object_type`, `price_type`
и `currency` константны и как признаки бесполезны.

### Правила слияния

Повторы объединяются **по ID объявления**, что не гарантирует объединение разных
объявлений одного физического дома. Для конфликтующих полей сохраняется первое непустое
значение в порядке отсортированных файлов, альтернативы попадают в `conflicts`; этот
порядок не означает выбор самого свежего объявления. Все источники сохраняются в
`sources`. Варианты одного фото на CDN объединяются по исходному пути, выбирается
максимальный размер из предоставленных ссылок; новые размеры ссылок не генерируются.

### Загрузка фотографий и этика

Загрузка последовательная, случайная пауза **2–5 секунд перед каждым запросом**,
таймаут соединения 10 секунд, чтения — 45 секунд, до 3 повторов при временных сбоях.
При HTTP 429/503 учитывается `Retry-After`, иначе применяется увеличивающаяся задержка.
При 401/403 или сохраняющемся 429 загрузка прекращается, датасет сохраняется.
Код завершения 2 означает остановку загрузки, 0 — завершение прохода (отдельные
фотографии при этом могут иметь статус `failed`). Редиректы не выполняются.

Заголовки содержат честный User-Agent и Accept для изображений; собственный идентификатор
с контактом задаётся через `--user-agent`. Скрипт не меняет IP, не вращает идентификаторы
и не обходит CAPTCHA. Паузы снижают нагрузку, но не гарантируют отсутствия блокировок.
Запрашиваются только ссылки `https://img.dmclk.ru` из таблиц; страницы объявлений не
загружаются. Используйте выгрузки и изображения с разрешённым для вашей задачи доступом.

## Пайплайн

Все скрипты запускаются из корня репозитория. Скрипты анализа принимают `--input`
(по умолчанию `data/dataset/objects.jsonl`), каталог отчётов — `--output-dir`
(в `build_reach_features.py` и `build_reach_llm_features.py` — `--report-dir`)
и `--verbose`. Обучающие скрипты принимают `--input`, `--experiments-dir` (корень
экспериментов) и `--verbose`. Сборщик датасета принимает
позиционный путь к выгрузкам и `--output`.

### 0. Сборка датасета из выгрузок (опционально)

```bash
python build_dataset.py "data/raw" --output "data/dataset" --no-download   # проверить разбор
python build_dataset.py "data/raw" --output "data/dataset"                # с фотографиями
```

Полезные ключи: `--recursive` для поиска в подпапках, `--delay-min/--delay-max` для паузы,
`--retries` для числа повторов, `--max-photos N` (`0` — все), `--max-image-mb`

Повторный запуск в ту же папку продолжает загрузку: журнал фотографий дополняется,
таблицы и исходные строки пересоздаются. Ctrl+C сохраняет прогресс. Не запускайте два
экземпляра в одну выходную папку.

### 3. Широкая матрица признаков → `data/features/features_rich.csv`, `reports/features_rich/`

python build_reach_features.py

продавца и площадки, one-hot шоссе и типов населённых пунктов, частотные кодирования
локаций, структура адреса и ссылки, а также флаги из текста описания
(`--no-text-features` оставляет только структурированные поля).

Матрица содержит `listing_id`, признаки, цель `asking_price_rub`, вариант цели

`reports/features_rich/feature_dictionary.csv` описывает каждую колонку, а

### 3.1. Признаки из текста объявления (DeepSeek API) → `data/features/features_llm.csv`, `reports/features_llm/`

```bash
python build_reach_llm_features.py --llm-limit 3   # пробный прогон на трёх объявлениях
python build_reach_llm_features.py                 # полный прогон, кэш продолжает работу
```

Языковая модель извлекает из текста объявления по фиксированному системному промпту
(`PROMPT_VERSION`) характеристики дома: площади, этажность, спальни и санузлы, год
постройки и ремонта, материалы стен, фундамента и кровли, толщины, коммуникации
(электричество, газ, вода, канализация, отопление, вентиляция), характеристики участка,
документы, расходы, дополнительные строения, включённое в продажу имущество, сообщённые
проблемы, противоречия и вопросы продавцу.

Матрица содержит **только** ключ `listing_id` и признаки `llm_*` — структурных признаков
в ней нет. Для обучения она соединяется со структурной матрицей из п. 3:

```python
structured = pd.read_csv("data/features/features_rich.csv")
llm = pd.read_csv("data/features/features_llm.csv")
matrix = structured.merge(llm, on="listing_id", how="left")
```

**Ключ API.** Скрипт обращается к DeepSeek API
(`https://api.deepseek.com/chat/completions`, режим `response_format={"type":"json_object"}`).
Ключ читается из `.env` (переменная `DEEPSEEK_API_KEY`) или из переменной окружения; сам
ключ не логируется и не попадает ни в кэш, ни в отчёт. Подготовка:

```bash
cp .env.example .env              # затем впишите свой ключ в .env
pip install -r requirements.txt   # добавляет python-dotenv
```

Модель и адрес задаются ключами `--model` (по умолчанию `deepseek-chat`), `--api-base-url`
(`https://api.deepseek.com`), `--api-key-env` (`DEEPSEEK_API_KEY`), `--env-file` (`.env`),
`--llm-temperature`. Текст объявления передаётся отдельным пользовательским сообщением.

**Статус запросов в консоли.** Каждый запрос печатает строку вида
`[3/1144 2074919436]  HTTP 200  попытка 1/3  8.4 с  токены 3369/2874  ok` — номер
объявления, HTTP-код, номер попытки, время ответа, токены и результат (`ok`, `не JSON`,
`некорректная схема`, `ошибка`, `ошибка сети`). Ключ `--verbose` дополнительно печатает
объявления, взятые из кэша. В конце выводится сводка: сколько извлечено, сколько взято из
кэша, сколько ответов не прошло схему и суммарный расход токенов. HTTP 401/402/403
прерывают прогон с сообщением об ошибке ключа или баланса.

**Проверка корректности JSON.** Каждый ответ разбирается и проверяется функцией
`validate_extraction`: наличие всех обязательных ключей верхнего уровня, все 50 полей
`features` и два поля `price_label`, допустимые статусы
(`stated/planned/possible/unknown/conflicting`), правило «значение без дословной
цитаты = null», правило `value=null, evidence=null` для `unknown`/`conflicting`, типы
значений и допустимые перечисления. При нарушении схема ответа перезапрашивается
(`--llm-retries`, по умолчанию 2) вместе с перечнем ошибок; если корректный JSON так и
не получен, объявление заменяется валидной «пустой» схемой, а в матрице поднимается флаг
`llm_extraction_failed`.

**Кэш и возобновляемость.** Ответы складываются в `data/features/llm_extractions.jsonl`
(ключ — `listing_id`, хеш текста, провайдер, модель и версия промпта). Повторный запуск не
переспрашивает модель для неизменённых объявлений; `--llm-limit N` обрабатывает только
первые N строк, `--llm-cache` задаёт другой файл кэша.

`price_label` (цена и цена за м²) извлекается **только для аудита** и не становится
признаком: цена — это целевая переменная. Покрытие и статусы по каждому полю пишутся в
`reports/features_llm/llm_field_summary.csv`.

### 3.2. Эмбеддинги описаний объявлений → `data/features/embeddings.csv`, `data/features/embeddings.npy`

```bash
ollama pull qwen3-embedding:8b      # один раз
python build_embeddings.py --limit 4   # пробный прогон на четырёх объявлениях
python build_embeddings.py             # полный прогон, кэш продолжает работу
```

Локальная модель `qwen3-embedding:8b` (Ollama, `POST /api/embed`) превращает описание
объявления в вектор признаков. В `data/features/` появляются:

- `embeddings.csv` — `listing_id` и колонки `emb_0000…emb_NNNN` (порядок строк как в датасете);
- `embeddings.npy` — та же матрица без id, `float32`, для быстрой загрузки;
- `embeddings_meta.json` — модель, размерность, счётчики, время;
- `embeddings_cache.jsonl` — кэш векторов для возобновляемого прогона.

Векторы по умолчанию L2-нормируются (модель обучена на косинусную близость), `--no-normalize`
сохраняет их как есть. Объявления без описания получают NaN-вектор и считаются в отчёте.
Каждый батч печатает строку статуса вида `[3/72]  HTTP 200  попытка 1/3  1.2 с  dim 4096  ok`;
при отсутствии модели (HTTP 404) прогон останавливается с подсказкой `ollama pull …`.

Настройки: `--model` (по умолчанию `qwen3-embedding:8b`), `--host`, `--batch-size` (16),
`--limit`, `--retries`, `--timeout`, `--normalize/--no-normalize`, `--cache`.

Для обучения матрица соединяется по `listing_id`:

```python
matrix = structured.merge(llm, on="listing_id", how="left")
                   .merge(pd.read_csv("data/features/embeddings.csv"),
                          on="listing_id", how="left")
```

Векторы — это представление текста, а не предсказание модели, поэтому утечки цели в них нет.

### 3.3. Компактная матрица: числовой каркас и 10 групп признаков → `data/features/features_v1.csv`, `reports/features_v1/`

```bash
python build_features_v1.py
```

Сжатый набор для быстрых экспериментов: **числовой каркас** из карточки объявления
(`house_area_m2`, `distance_to_mkad_km`, `highway`, `land_area_sotka`, `floors`,
`house_area_per_floor`, `land_to_house_ratio`) и **10 групп признаков**: девять из них
собираются из извлечений текста, группа «Земля» — из меток карточки и извлечений.

| Группа | Уровни |
| --- | --- |
| Земля | ИЖС / СНТ / ДНП / ЛПХ / земли населённых пунктов / сельхозназначение / другие |
| Отделка | без отделки / предчистовая / готовая / частичная / неизвестно |
| Газ | подключён / по границе / рядом / отсутствует / неизвестно |
| Стены | газобетон / пенобетон / кирпич / каркас / брус / бревно / другие / неизвестно |
| Фундамент | плита / ленточный / сваи / свайно-ростверковый / другой / неизвестно |
| Отопление | газовое / электрическое / печное / твёрдотопливное / другое / неизвестно + работоспособность |
| Вода и канализация | скважина / колодец / центральное / привозная вода / другое + тип канализации и подключение |
| Планировка | спальни, санузлы, мансарда, подвал |
| Дополнительные строения | баня, гараж, гостевой дом: наличие и наибольшая площадь |
| Возраст | год постройки и год реконструкции |

Карточка приоритетна: извлечения только заполняют пропуски каркаса. У группы «Земля»
источники идут по порядку: метки карточки `land_use_label`, затем вид разрешённого
использования, затем категория земель из извлечений. Свободный текст
схлопывается в канонический уровень («газобетонные блоки», «газоблок», «газобетон» →
`gazobeton`), нераспознанное попадает в `other`, отсутствующее — в `unknown`; колонки
словаря выводятся всегда, поэтому схема матрицы не зависит от выборки.

Значения используются, только если статус входит в `--llm-statuses` (по умолчанию
`stated`): промпт (`prompts/prompt_v1.txt`) различает существующее, запланированное и
возможное, а газ по границе — не подключённый газ. `--one-hot-min-count` управляет только
частотами шоссе, `--no-llm-fill` оставляет один каркас. Пропуски остаются NaN, признаки,
производные от цены, не строятся.

Матрица содержит `listing_id`, признаки, цель `asking_price_rub`, вариант цели
`log_asking_price_rub` и ключ групп `group_locality`. Отчёт
`reports/features_v1/report.md` показывает колонки и покрытие по группам, канонические
уровни, расхождения карточки и извлечений и раскладку по статусам.

### 3.4. Компактная матрица v2: каркас + группы из локальной модели → `data/features/features_v2.csv`, `reports/features_v2/`

```bash
python build_features_v2.py            # полный проход по 1144 объявлениям
python build_features_v2.py --limit 20 --verbose   # быстрая проверка на 20 объявлениях
```

Отличие от `build_features_v1.py`: пропуски каркаса и все группы извлекает локальная
модель **Ollama** (`qwen3.8` по умолчанию, `--model`, `--host`), а не внешний API, и
работают два промпта — `prompts/prompt_v2_cat.txt` (категориальные признаки) и
`prompts/prompt_v2_num.txt` (числа: площади, этажность, расстояние, год постройки,
планировка, дополнительные строения). Ответы кэшируются в
`data/features/llm_v2_extractions.jsonl` вместе с хешем текста объявления, хешем обоих
промптов, хешем схемы ответа и именем модели.

Кэш — точка возобновления: каждый готовый ответ **дописывается и сбрасывается на диск
(`flush` + `fsync`) сразу после объявления**, поэтому даже отключение питания не заставляет
начинать заново — следующий запуск той же команды прочитает готовые ответы и запросит
только остаток. Обрыв записи не портит файл: неполная последняя строка распознаётся и
починяется при старте, а её объявление просто запрашивается снова. Правка промпта или
изменение набора полей автоматически инвалидирует кэш, `--refresh` перезапрашивает всё
заново, `--parallel N` ускоряет проход.

Прогресс виден в консоли без `--verbose` — каждые `--log-every` (по умолчанию 10)
объявлений печатается скорость, оставшееся время и размер кэша:

```
Кэш: data/features/llm_v2_extractions.jsonl
      на диске 120 записей (612 КБ); актуальных ответов для этой выборки: 120
Модель: qwen3.8 на http://127.0.0.1:11434; рассуждения: выключены; параллельно: 1 объявл.
Промпты: prompt_v2_cat.txt + prompt_v2_num.txt (sha 72b87f0c54ce6865); версия промпта 2.0, схема ответа 86e65a18
Объявлений в выборке: 1 144; берётся из кэша: 120; нужно запросить: 1 024 объявления (по 2 запроса на объявление)
Оценка времени: ~5 ч 41 мин (до 01:12). Каждый готовый ответ сразу пишется на диск, поэтому при отключении питания прогон продолжается с этого места.
Прогресс: строка каждые 10 объявлений (--log-every 0 отключает их).

  [130/1 024] 2056920219: 21.7 с, заполненных полей 24
Прогресс: 130/1 024 (12.7%); скорость 2.8 объявл./мин; прошло 46 мин; осталось ~5 ч 19 мин (к 00:50); ошибок 0; кэш 664 КБ
```

Ключи консоли: `--verbose` добавляет строку по каждому объявлению, `--log-every 0`
оставляет только итоговую сводку. После прогона печатается сводка по группам признаков,
пути артефактов и, если часть объявлений осталась без ответа, подсказка перезапустить ту
же команду, чтобы добрать недостающее.

Словари уровней жёстко зафиксированы, поэтому матрица сравнима между прогонами:

| Группа | Уровни |
| --- | --- |
| Земля | `izhs` (ИЖС и земли населённых пунктов) / `snt` (СНТ и ДНП) / `lph` / `other` / `unknown` |
| Отделка | `with_repair` / `without_repair` (включая предчистовую и неизвестное) |
| Газ | `podklyuchen` / `po_granice` / `otsutstvuet` (включая неизвестное) |
| Стены | газобетон / пенобетон / кирпич / каркас / брус / бревно / `other` / `unknown` |
| Фундамент | плита / ленточный / сваи / свайно-ростверковый / `other` / `unknown` |
| Отопление | `gazovoe` / `gazgolder` / `elektricheskoe` / `pechnoe` / `otsutstvuet` |
| Вода | `centralnoe` / `skvazhina` / `kolodec` / `otsutstvuet` |
| Канализация | `centralnoe` / `septik` / `otsutstvuet` |
| Планировка | `bedrooms`, `bathrooms`, `attic_present`, `basement_present` |
| Дополнительные строения | `bathhouse_present`, `bathhouse_area_m2`, `garage_*`, `guest_house_*` |
| Возраст | `house_age` = 2026 − год постройки |

Группы без уровня «other» схлопывают неизвестное в свой отрицательный уровень
(`otsutstvuet`, `without_repair`) — так задан словарь; строки, по которым модель вообще
не отвечала, остаются NaN. Значения вне осмысленного диапазона (например, «баня 400 м²»)
заменяются на NaN и попадают в таблицу проверки диапазонов. Цена и метки платформы в
промпт не передаются: извлечения становятся признаками, поэтому утечка цели исключена.
`--no-llm` собирает матрицу только из полей карточки и не требует Ollama.

Матрица использует те же служебные колонки, что и остальные (`listing_id`, цель
`asking_price_rub`, вариант цели `log_asking_price_rub`, ключ групп `group_locality`),
поэтому обучающие скрипты принимают её напрямую:

```bash
python train_histgb.py --input data/features/features_v2.csv
```

Оговорка для прогонов без модели: с `--no-llm` все колонки групп остаются пустыми, а
`HistGradientBoostingRegressor` из scikit-learn 1.9 не может обучить бинаризацию на
полностью пустой колонке, поэтому такую матрицу перед обучением нужно очистить:
`matrix.drop(columns=[c for c in matrix if matrix[c].isna().all()])`. После полного
прохода с моделью пустых колонок не остаётся (кроме редких уровней шоссе).

Отчёт `reports/features_v2/report.md` дополнительно содержит заполненность полей
извлечения, раскладку по каноническим уровням, покрытие колонок и расхождения карточки и
извлечений. Полный проход по всем объявлениям занимает часы: два запроса на объявление к
локальной модели, на этом датасете (1144 объявления, `qwen3.8` на CPU/GPU без рассуждений)
— примерно 20–25 секунд на объявление, то есть ~7 часов без `--parallel`. Прогресс виден
в консоли по умолчанию, а прерванный прогон продолжается той же командой с того же места.

### 4. Базовая модель: линейная регрессия → `experiments/<NN>/`

```bash
python train_lin_reg_2f.py
```

`LinearRegression` на двух признаках, 5-фолдовая кросс-валидация, метрики out-of-fold,
коэффициенты, диагностика остатков по квартилям прогноза и графики.

### 5. Основная модель: градиентный бустинг → `experiments/<NN>/`

```bash
python train_histgb.py
```

`HistGradientBoostingRegressor` с early stopping на широкой матрице. По умолчанию цель
моделируется в логарифме и пересчитывается в рубли через `expm1`, прогнозы обрезаются
по диапазону обучающей части фолда, а валидация групповая.

Полезные ключи: `--cv {group,kfold}`, `--folds`, `--seed`, `--max-iter`,
`--tune N` (случайный поиск гиперпараметров на внутренней разбивке обучающей части
фолда — тестовый фолд в подборе не участвует), `--inner-folds`,
`--importance-repeats`, `--no-clip-predictions`.

Отчёт содержит метрики на лог-шкале и в рублях, разбивку по фолдам, сравнение с базовой
моделью предсказания среднего, permutation importance, посчитанную на тестовых фолдах,
и диагностику остатков.

### 6. kNN-регрессия → `experiments/<NN>/`

```bash
python train_knn.py
```

`KNeighborsRegressor` на компактной матрице (п. 3.3): прогноз — взвешенное по расстоянию
среднее цен `k` ближайших объявлений. kNN не умеет работать с NaN и чувствителен к
масштабу, поэтому в `Pipeline` перед моделью стоят `SimpleImputer(median)` и
масштабирование (`--scaler standard|robust|none`); и то и другое обучается **только на
обучающей части фолда**, поэтому тест в заполнение пропусков и в масштаб не попадает.
Обрезка прогнозов не нужна: на лог-шкале прогноз — выпуклая комбинация целей соседей и
не выходит за диапазон обучающей части фолда.

Полезные ключи: `--cv {group,kfold}`, `--folds`, `--seed`, `--n-neighbors`, `--weights
{uniform,distance}`, `--p {1,2}`, `--scaler`, `--tune N` (случайный поиск `n_neighbors`,
`weights`, `p` на внутренней разбивке обучающей части фолда), `--inner-folds`,
`--importance-repeats`.

Отчёт содержит метрики на лог-шкале и в рублях, разбивку по фолдам, сравнение с базовой
моделью, permutation importance и диагностику остатков. Пример запуска на своей матрице:
`python train_knn.py --input data/features/features_rich.csv --experiments-dir experiments`.

## Условия воспроизводимости

- Случайность зафиксирована: `--seed 42` во всех скриптах обучения, `KFold`/`GroupKFold`
  с перемешиванием и фиксированным зерном.
- Разбиение по умолчанию в основной модели — `GroupKFold` по `group_locality`:
  объявления одного населённого пункта не попадают одновременно в обучение и тест.
  Режим `--cv kfold` даёт более оптимистичную оценку и предназначен только для быстрых
  сравнений — при сверке со статьёй указывайте использованный режим.
- Разброс метрик по фолдам заметно зависит от зерна: несколько очень дорогих объектов
  попадают в разные тестовые части. Сравнивайте модели по среднему **и** стандартному
  отклонению по фолдам, а не по одной цифре.
- Целевая переменная сильно скошена, поэтому RMSE чувствителен к единичным объектам;
  в отчётах рядом приведены MAE и медианная абсолютная ошибка.
- Отчёты EDA и признаков пересоздаются запуском скрипта поверх прежних результатов:
  чтобы сохранить прежний прогон, укажите другой `--output-dir` (в
  `build_reach_features.py` — `--report-dir`). Обучающие запуски не перезаписываются:
  каждый получает новый номер в `experiments/`.

## Целостность данных и известные ловушки

Эти пункты проверены на текущей выгрузке и важны для корректной сверки результатов.

- **Цена предложения, не сделки.** `asking_price_rub` — запрошенная цена из объявления.
  Метрики описывают рынок предложения, а не цены сделок.
- **Производные цены запрещены как признаки.** `price_per_m2_advertised` и
  `price_per_m2_computed` считаются из целевой переменной; в широкой матрице они
  намеренно не создаются.
- **Метка «Выгодная цена».** Платформа присваивает её по относительной цене: внутри
  диапазонов площади такие объявления концентрируются у нижней границы распределения
  цены за м². Признак исключён как утечка цели и не входит в `badge_count`.
- **`badge_mortgage_discount_pct` исключён.** Градация скидки на ипотеку оказалась
  связана с относительной ценой немонотонно (Спирмен 0,82): похоже, она определяется
  договором продавца, а не свойством дома, то есть это прокси сегмента, а не
  характеристика объекта. Признак в широкой матрице **не создаётся**.
- **Пропуски нельзя удалять построчно.** В широкой матрице пропуски есть в подавляющем
  большинстве строк, поэтому построчное удаление уничтожило бы почти весь датасет.
  `HistGradientBoostingRegressor` обрабатывает NaN сам; для линейных моделей заполняйте
  пропуски медианой, посчитанной **только на обучающей части фолда**.
- **Разделяйте по объектам, а не по строкам.** Дедупликация идёт по `listing_id` и не
  объединяет разные объявления одного дома; используйте группировку (в репозитории —
  по населённому пункту через `group_locality`, либо по нормализованному адресу).
- **Конфликты площади.** `conflicts` сохраняет расхождения между карточкой и описанием —
  требуют отдельной проверки перед обучением.
- **Возраст объявления.** `listing_age_text` — исходный текст («7 часов назад») либо дата.
  Дата выгрузки в данных отсутствует, поэтому абсолютный возраст восстанавливается
  относительно контрольной даты (`--reference-date`, по умолчанию — самая поздняя дата
  в данных). Это приближение, а не измерение.
- **Фотографии.** `photo_paths` заданы относительно выходного каталога сборки. В
  канонической копии `data/dataset/` изображений нет, они лежат в legacy-каталоге
  `dataset/photos/`; скрипты анализа признаков по изображениям не строят. Для
  мультимодальных экспериментов исключите цену и её упоминания на фото и в тексте
  описания.
- **Метки продавца и площадки не проверены** и не являются техническими характеристиками.
- **При другой схеме экспорта** обновите отображение заголовков в `parse_row`:
  неизвестные ячейки останутся в `raw_rows.jsonl`.
